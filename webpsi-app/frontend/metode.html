Metode verifikasi METplus

Halaman ini menjelaskan cara membandingkan prakiraan InaNWP dengan observasi GSMAP NRT pada grid yang sama, beserta metrik yang dipakai.

1. Workflow end-to-end

1
Kumpulkan input
Forecast: wrfout / NetCDF InaNWP. Observasi: GSMAP NRT hourly NetCDF dari FTP himawari6/GSMaP/netcdf.
2
Siapkan field yang sebanding
Hujan model sering akumulasi (RAINNC) → diubah ke interval (mis. 3 jam). GSMAP rainrate dijumlah pada interval yang sama.
3
RegridDataPlane
Observasi di-regrid ke grid model (metode BUDGET) agar setiap sel grid punya pasangan forecast–obs.
4
GridStat
Hitung skor kontinu & kategorikal di seluruh domain (mask FULL / wilayah tertentu).
5
Publikasi dashboard
File .stat dan ringkasan JSON disalin ke webpsi; aplikasi ini hanya membaca output.

2. Mengapa grid-to-grid?

GSMAP adalah data hujan gridded satelit. Membandingkannya dengan field hujan InaNWP pada grid yang sama memungkinkan evaluasi pola spasial (bukan hanya di titik stasiun). Verifikasi titik stasiun (grid-to-point / PointStat) dapat ditambahkan kemudian.

3. Metrik yang dihasilkan GridStat

Continuous (CNT)

  • RMSE — magnitude error rata-rata (semakin kecil semakin baik)
  • ME / Bias — kecenderungan over/under-estimate
  • MAE — rata-rata absolut error

Categorical (CTS / CTC)

  • Threshold contoh: >0.1, >1, >5, >10 mm
  • POD / Hit Rate, FAR, CSI / ETS, Frequency Bias
  • CTC menyimpan hit, miss, false alarm, correct negative

Rujukan umum: panduan verifikasi prakiraan WMO; Jolliffe & Stephenson — Forecast Verification; dokumentasi METplus/MET (DTC).

4. Output file METplus

  • *.stat — tabel skor ASCII (CNT, CTS, CTC, …)
  • *_pairs.nc — NetCDF field forecast, observasi, dan selisih (untuk peta)

5. Batasan & catatan operasional

  • Selalu cek START_DATE / waktu valid di wrfout — nama file bisa menyesatkan.
  • Unit dan interval accum model vs observasi harus konsisten.
  • Dashboard tidak menjalankan WRF; hanya menampilkan skor yang sudah dihitung di DPU.
